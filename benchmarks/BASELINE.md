# Greedy Optimizer v1 — performance baseline

This records the measured cost of the current, frozen **Greedy Optimizer v1**
(`app/optimizer.py`'s `optimize_day_schedule` /
`combine_fixed_and_optimized_scheduled_tasks`) on the legacy CSV pipeline
(`app/data_processor.py`), exactly as `app/main.py` and `app/app.py` call it
today. It exists so a future optimizer change (see the project's Task 6) has
a real, reproducible number to compare against instead of a guess. Nothing
here changes optimizer behavior, and no second production optimizer is kept
around — this only calls the one real entry point.

## Method

- Script: [`benchmarks/optimizer_baseline.py`](optimizer_baseline.py)
  (`python -m benchmarks.optimizer_baseline`). Standard library only
  (`time.perf_counter`, `statistics`, `platform`, `json`, `argparse`).
- Fixtures (all single-day, "day 1"):
  - `samples/inputs/valid_single_day_basic.csv` — checked-in sample (4 fixed
    blocks, 3 flexible tasks).
  - `samples/inputs/dependency_chain_linear.csv` — checked-in sample (2 fixed
    blocks, a 4-task linear dependency chain).
  - `benchmarks/fixtures/synthetic_medium_day.csv` — generated by
    [`generate_fixtures.py`](generate_fixtures.py) with a fixed seed (`42`):
    4 fixed blocks + 15 flexible tasks, varied durations/priorities/
    categories, ~30% of tasks carrying a dependency on an earlier task.
  - `benchmarks/fixtures/synthetic_larger_day.csv` — same generator, seed
    `43`: 4 fixed blocks + 40 flexible tasks.
  - Regenerating the synthetic fixtures (`python -m
    benchmarks.generate_fixtures`) is deterministic and reproduces the same
    rows byte-for-byte, since task order, durations, priorities, categories,
    tags, and dependency edges are all drawn from a seeded `random.Random`
    with no other source of randomness.
- Configuration is fixed: no `config_path` is passed, so scoring runs on
  `RewardSettings`' built-in defaults — the same defaults `app/main.py` and
  `app/app.py` use today (see `app/reward.py`'s module docstring on the
  YAML-discovery mismatch).
- **Import time** (CSV parsing + Pydantic model construction, via
  `load_schedule_from_csv`) and **optimize time** (the greedy search itself,
  via `combine_fixed_and_optimized_scheduled_tasks`) are timed separately,
  each with its own warmup and repeat count, so import cost never leaks into
  the optimizer number.
- Per fixture: 3 warmup iterations (discarded), then 15 measured repeats.
  Median and population standard deviation (spread) are reported in
  milliseconds, along with min/max.
- Fixture sizes (fixed-block count, flexible-task count) and the resulting
  scheduled/unscheduled counts and total score are recorded alongside the
  timings, so a future comparison can confirm it is measuring an equivalent
  scenario.

## Environment (as measured)

- Python: 3.10.11 (MSC v.1929 64 bit (AMD64))
- Platform: Windows-10-10.0.19045-SP0
- Processor: AMD64 Family 25 Model 33 Stepping 2, AuthenticAMD

Re-run with `python -m benchmarks.optimizer_baseline` to reproduce on a
different machine; raw output is written to
`benchmarks/results/greedy_v1_baseline.json`.

## Measured baseline results

| fixture | fixed blocks | flexible tasks | scheduled | unscheduled | total score | import median (ms) | optimize median (ms) | optimize spread (min–max, ms) |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| valid_single_day_basic | 4 | 3 | 7 | 0 | 89.00 | 0.1705 | 3.8268 | 3.6325–4.1091 |
| dependency_chain_linear | 2 | 4 | 6 | 0 | 178.00 | 0.1587 | 3.0053 | 2.8055–3.2169 |
| synthetic_medium_day | 4 | 15 | 16 | 3 | 341.18 | 0.2873 | 31.5305 | 30.6831–33.1705 |
| synthetic_larger_day | 4 | 40 | 14 | 30 | 463.63 | 0.4456 | 84.0762 | 82.3489–88.3323 |

(Full precision, including stdev, sample counts, and environment metadata,
is in `benchmarks/results/greedy_v1_baseline.json`.)

## Reading the numbers

- Import time is consistently sub-millisecond and grows only mildly with
  fixture size (CSV parsing + Pydantic validation dominate, not scheduling).
- Optimize time grows steeply with flexible-task count: the 40-task fixture
  (`synthetic_larger_day`) takes roughly 22x longer to optimize than the
  3-task fixture (`valid_single_day_basic`), consistent with Greedy
  Optimizer v1's per-iteration cost (it rescans every remaining task's full
  30-minute-grid candidate set on every placement — see
  `app/optimizer.py`'s `_best_candidate_for_task`/main loop).
- `synthetic_larger_day` leaves 30 of 40 flexible tasks unscheduled: with
  only ~10.5 hours of non-fixed day left after 4 fixed blocks and no task
  ever being moved once placed, this is an expected greedy/capacity
  limitation on a deliberately oversubscribed day, not a bug in the
  benchmark.

## Limitations

- Windows wall-clock timing has coarser resolution and more scheduler jitter
  than a dedicated Linux CI runner; the reported spread reflects that, not
  algorithmic variance. Re-running on the CI runner's environment would
  likely show a smaller spread at similar medians.
- Single-process, single-run measurement (no `perf`/hardware counters); this
  is a practical, reproducible baseline for a future greedy-vs-alternative
  comparison, not a rigorous micro-benchmark.
