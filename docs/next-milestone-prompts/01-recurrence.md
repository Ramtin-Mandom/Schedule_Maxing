Required design and implementation:

1. Extend the current recurrence representation. A series definition is not itself eligible for scheduling. Materialize a distinct canonical Task for each occurrence, with explicit immutable series/slot identity and provenance; do not set its recurrence rule and accidentally treat it as another series. Keep placements and execution snapshots separate. Add explicit local series start date and IANA timezone rather than deriving an anchor from the requested expansion range or machine clock. Existing ambiguous templates require a visible needs-configuration state unless an unambiguous stored anchor can be proven.
2. Use a deterministic occurrence ID derived from stable series identity and original local recurrence slot, plus database uniqueness on that tuple in both storage backends. Mutable placement date and mutable definition version are not identity inputs. Include owner validation. Tombstones/exceptions reserve suppressed slots so expansion cannot resurrect them. Two devices expanding the same rule must converge; differing snapshots from concurrent edits must conflict rather than mint another occurrence.
3. Expansion takes an explicit inclusive date range, bounded by the existing planning-range limit and an additional materialized-row/work budget. Bound scanning as well as output: do not iterate from a decades-old anchor one day at a time without a cap or arithmetic seeking. Repeated/overlapping expansion, restart and retry are no-ops for existing unchanged occurrences. Wire expansion before allocation in the persisted generation paths, in background work on desktop.
4. Specify and implement calendar semantics: daily every N days from anchor; weekly Monday-anchored weeks every N weeks, selected weekdays or anchor weekday; monthly every N months, explicit day or anchor day. Exclude dates before anchor. Skip nonexistent month days rather than clamp them; count counts valid recurrence slots from the series anchor, independent of the requested window, and exceptions consume their original slot. End date is inclusive. Keep the existing prohibition on count plus end date. Test Jan 31, February, leap years and sparse far-future requests.
5. Slots are local dates in the series timezone, unaffected by device timezone or movement. Preserve `planning/time.py`'s explicit rejection of ambiguous/nonexistent instants and offset-transition scheduling windows; expansion of a date need not mean that an unsupported window can be scheduled. Report affected slots/windows, never silently shift times. Store UTC instants for placements and use UTC elapsed duration. Define timezone edits as a versioned series change; do not rekey historical occurrences.
6. Add first-class synchronized exception/override records or equivalent normalized fields, with versioned operations for “this occurrence”, “this and future occurrences”, and “entire series”. A single-occurrence edit affects its concrete task/override; skip/delete prevents regeneration. Future changes use an atomic cutoff/series-segment operation with explicit lineage and suppression of superseded slots. Changes must not create overlapping successor definitions or duplicate slots. Preserve completed/in-progress/paused occurrences, execution records, and explicit manual overrides; explain which records were preserved. Never hard-delete history. If multiple exception records are needed, enforce uniqueness per slot/scope.
7. Moving an occurrence, including across dates, retains its original slot identity and cannot recreate the original date's work. Adapt `occurrence_key`, supersession and reschedule validation accordingly. Migrate legacy recurring-template placements into identity mappings, grouping existing same-date lineage; retain placement/execution IDs and immutable historical snapshots. Do not rewrite old execution task IDs merely to fit the new shape. Detect ambiguous legacy collisions and expose a repair conflict instead of discarding records.
8. Define dependency rules explicitly: ordinary dependencies target the existing concrete task; recurring-to-recurring dependencies resolve the same original slot in a compatible timezone/series cadence, never every occurrence or an arbitrary latest placement. Reject unsupported mismatched cadences/timezones, cycles and unresolved prerequisites with useful errors. Ordinary tasks must select a concrete prerequisite occurrence when depending on a series. Bound prerequisite expansion and retain external-dependency semantics.
9. Implement owner-scoped service/API operations, normalized live/revision storage, migration rollback tests, mapping/snapshot updates, CSV compatibility, and basic sync serialization/ordering/idempotent compound operations for these records. Preserve protocol replay and account ownership. Prompt 3 hardens conflict recovery; do not leave this feature silently losing exceptions over sync meanwhile. Define capability/version negotiation so older clients cannot erase unknown identity/exception data. Surface recurrence configuration and scoped edits/deletes through the reusable desktop form/controller UI using existing workers; do not build another task editor.
