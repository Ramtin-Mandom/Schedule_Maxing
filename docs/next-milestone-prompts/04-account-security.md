Implement:

1. Owner-independent recovery request by email/identifier, a configured delivery adapter, recovery-link landing/reset UI, token validation and password reset. Wire “Forgot password” into the current desktop account UI; a hosted minimal reset page or a desktop token-entry flow must actually consume the delivered credential. Do not require an existing login. Offline-only users get accurate configuration messaging. Keep direct desktop dependency boundaries: shared recovery logic must not force FastAPI/JWT into the direct package profile. Direct mode remains private development, not a secure distribution model for database credentials.
2. Generate cryptographically random recovery credentials; persist only a digest with user binding, expiration and consumed/revoked state. Bound outstanding tokens and define re-request invalidation. Consume via a conditional update/row lock atomically with password change and session invalidation, so concurrent requests and replay yield exactly one success. Never return recovery credentials in ordinary API responses. Use the existing password validation and Argon2id hashing.
3. Use generic request responses for known/unknown accounts and avoid an obvious timing distinction. Do not leak existence via response codes, delivery errors or per-account throttling. Delivery is injectable and mocked in tests; provide a real configurable adapter with timeout/error handling, not merely console token output. Define retry behavior so delivery failures do not corrupt recovery state or expose the link. Never claim production readiness without configured and verified delivery.
4. After reset, revoke browser sessions and invalidate existing bearer JWTs, for example with a dedicated credential epoch checked against server state on every authentication. Do not overload ordinary profile version. Check login/reset concurrency and token issuance so a credential check completed before reset cannot issue a usable new session afterward. Define migration behavior for pre-epoch JWTs explicitly. Direct authenticated workspaces also need credential-change invalidation at service boundaries. Do not auto-login after reset; sync reauthentication retains pending local data from Prompt 3.
5. Build links from a validated configured public HTTPS origin/path, never untrusted Host/forwarded headers. Prevent open redirects; protect reset pages with no-store and no-referrer behavior and avoid third-party content. Redact token-bearing query strings at application/proxy access-log boundaries or choose a fragment/token-entry exchange design that keeps secrets out of request URLs. Do not log request bodies, password hashes, tokens, database URLs or delivery secrets. Tests must inspect captured logs and validation errors for leakage.
6. Add authentication/recovery throttling for login, browser login, registration as appropriate, recovery requests and reset attempts. Use shared atomic state across workers/replicas (prefer existing PostgreSQL when suitable, with bounded retention and cleanup). Specify keys, windows, limits, Retry-After and limiter-failure behavior. Do not claim process-local counters protect multi-worker deployments. Trust forwarded IPs only from configured trusted proxies; test spoofed headers and two independent app instances sharing the limiter.
7. Audit and test ownership for task, occurrence, exception, placement, execution/session, analytics, preferences and sync endpoints including related references and compound operations. Existing owner-scoped services should be reused. Cross-user IDs return the existing non-disclosing refusal and write nothing. Check recovery credentials cannot target another account through body fields.
8. Reuse existing page/push/range/CSV/metadata limits, then fill gaps: bound full request bytes before unbounded parsing where practical, string/list sizes, dependency counts, expansion output/work, scheduling task counts/candidate work, analytics windows and sync batch bytes as well as operation count. Return deterministic structured errors. Bound expensive scheduling by cooperative work/deadline checks with atomic no-save on exhaustion; an HTTP timeout alone cannot stop a worker later committing results.
9. Add appropriate hosted connect/pool/statement and outbound delivery/network timeouts, safe production errors, explicit allowed hosts/origins and credential-aware CORS, and documented trusted proxy/TLS configuration. Preserve browser CSRF/origin checks; ALLOWED_ORIGINS currently participates in CSRF logic and is not evidence that CORS middleware is installed. Keep localhost development usable through explicit settings. Validate required secrets without printing their values. Separate application guarantees from reverse-proxy/body/time-limit settings that the operator must supply.

Migrations/API compatibility: append migrations from actual heads; preserve normalized storage and revision mapping. Existing valid accounts remain usable. Document intentional old-session invalidation and new capabilities; no hidden server startup migration or production settings edits. Keep offline desktop imports independent from optional web/database packages.
