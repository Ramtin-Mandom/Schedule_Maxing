Required behavior:

1. Inventory the protocol's entity types, versions, transactional boundaries, cursor advancement, replay and ordering against Prompts 1–2. Compound series edits/deletes/exceptions and reschedules must be atomic on the server and locally applied as coherent related records. Define version preconditions for the series and affected scope so concurrent expansion cannot evade a series edit. Preserve user/account isolation in every reference, operation log, shadow and conflict record.
2. Stale consequential writes return a durable conflict, not last-write-wins. Retain submitted local intent, server snapshot, base version, entity/occurrence IDs, dependent/related records and reason until resolution. Server pulls must not overwrite unsent local edits or execution sessions. Uniqueness convergence of deterministic occurrences must distinguish identical expansion from incompatible edits; never silently discard divergent execution history.
3. Extend existing account conflict UI with readable series slot, exception, manual placement and execution differences, affected records, and safe resolution choices. “Keep local” prepares a NEW operation against the displayed server revision, with the desired intent still subject to current constraints and ownership checks. If the server changes again before push, produce another conflict. Never force-write or blindly reuse an op-id with a different payload. “Accept remote” reconciles related local records without orphaning work or deleting unacknowledged actual execution history; history needing reconciliation remains visible. Tombstones must not be resurrected by keep-local.
4. Retain same-op-id replay for transport retries, immutable multi-record results, durable pending data across restart and atomic acknowledgement/shadow changes. Verify retries after server commit/lost response, partial page delivery, local crash before acknowledgement/cursor commit, and account switch mid-request. A page must advance its cursor only after its records are durably applied. Resume dependency-ordered records without duplicate occurrences, placements, executions or work sessions.
5. Temporary connection failures retain intent and use bounded backoff; malformed/permanently rejected operations become actionable errors rather than infinite retry loops. Auth expiry suspends authenticated sends, retains outbox/conflicts and offers sign-in/retry in existing UI. Never upload one account's queue using another account's token. Respect workspace guards and database lifecycle; stale worker results cannot repaint the new account's UI.
6. Clarify deletion/exception retention: a deleted series and skipped/deleted occurrence must remain suppressed after offline expansion or a late device reconnect. Define retention/cursor behavior explicitly; no premature tombstone/operation pruning. Keep revision histories needed for execution/lineage. Preserve stable ordinary-task IDs and old sync payload compatibility through capability negotiation; unsupported clients get clear upgrade errors rather than destructive field omission.
7. Recovery controls run network/database work through the existing worker architecture. No tokens, passwords or raw sensitive payloads in logs. Do not add blanket broad-exception success paths. Direct PostgreSQL uses existing version-conflict behavior instead of pretending it has an offline outbox; keep its UI wording accurate.
